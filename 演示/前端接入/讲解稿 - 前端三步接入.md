# 讲解稿 - 前端三步接入（10 分钟版：连视频 → 接文字 → 语音三节点）



> 本模块是为了解决厨房的一个痛点，在厨房里面手忙脚乱，满手油污根本腾不出来打字的问题，为此我设计了三大任务解决此问题，先把视频流接入，让系统能“看见”，再把文字聊天接入，跑通基础对话功能，最后再接入语音交互，做到完全不用触碰屏幕也能做到操作。

---

## 任务1：接入视频流（2 分钟）

**【讲 — 40 秒】**

> 首先来开始任务1：接入摄像头，接入的思路很简单，摄像头画面由后端常驻采集，前端只负责播放和截帧。真正花功夫的是**压缩**——因为视频帧要送给 VLM 视觉模型做识别，原图高清传过去又慢又占带宽，我们做了**等比缩放 + JPEG 压缩**，兼顾识别精度和传输效率。首先我来完成接入摄像头接入的核心代码。

**【代码 — 后端 OpenCV 采集】**（对应 `backend/app/usb_camera.py`）

```python
import cv2  在这先导入opencv的包然后开始建立摄像头的索引，设置目标分辨率，循环读取帧率，然后jpg编码压缩。# OpenCV：后端常驻采集

cap = cv2.VideoCapture(0)                        # 打开摄像头（设备索引0）
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 1280)          # 目标分辨率
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 720)

ok, frame = cap.read()                           # 循环读帧
ok, buf = cv2.imencode(".jpg", frame, [cv2.IMWRITE_JPEG_QUALITY, 85])  # JPEG编码
# 最新帧存入内存 → 前端经 /usb-camera/stream 取流
```

**【讲 — 50 秒】**

**【代码】**

// ① 回车即发：一行监听
if (e.key === "Enter" && !e.shiftKey) {

// ② 创建发送的文字字段（要发什么，逐项列出）

## 任务3：语音交互（5 分钟，三节点）

> 语音是全场核心。我们拆成三个功能节点：**降噪唤醒、流式识别、随时打断**，逐个讲核心代码并实操。

### 节点① 降噪唤醒（1.5 分钟）

**【讲 — 40 秒】**

> 厨房里炒菜声、抽油烟机声很大，直接语音识别会误触发。所以我们**前端实时计算音量做降噪**，先过滤无效噪音，只把有效人声推给设备端唤醒引擎，命中「小云小云」才应答。这里有个关键坑：浏览器自动播放策略会挂起音频，**必须点一下页面才会生效**，所以演示前排障动作就是"点一下页面"。

**【代码】**（对应 `frontend-2/src/lib/wakeword-stt.ts` 的 `calculateRmsVolume`、`openKws`）

```typescript
// 降噪：实时音量计算，滤除环境风噪
function calculateRmsVolume(samples) {
  let sum = 0;
  for (const s of samples) sum += s * s;
  return Math.min(100, Math.round(Math.sqrt(sum / samples.length) * 200));
}

// 有效人声推流给端侧 KWS，命中唤醒词才应答
kwsWs.onmessage = (m) => {
  if (msg.event === "wakeword") onKwsHit();   // 命中"小云小云"
};
```

**【实操】**

先点页面解锁音频 → 开「唤醒词」开关 → 喊「小云小云」→ 播"你好我在！"。收口："这一节点解决的是——**能不能叫醒**。"

### 节点② 流式识别（1.5 分钟）

**【讲 — 40 秒】**

> 传统语音要等整句话说完再去识别，卡顿明显。我们把音频**按帧分片、边录边转**：麦克风每帧降采样到 16kHz、转成 PCM 推给端侧 ASR，识别结果是流动的、边走边转写上屏。

**【代码】**（对应 `frontend-2/src/lib/wakeword-stt.ts` 的 `onaudioprocess` 推流循环）

```typescript
// 100ms 级分片推流：降采样 + 转 PCM16，边走边转写
processor.onaudioprocess = (e) => {
  const input = e.inputBuffer.getChannelData(0);
  const ds = downsampleBuffer(input, ctx.sampleRate, 16000); // 降采样16k
  const pcm16 = floatTo16BitPCM(ds);                        // 转16bit PCM
  asrWs.send(pcm16.buffer);                                 // 推给端侧ASR
  // 端侧 ASR 返回 partial 文本 → 实时上屏
};
```

**【实操】**

紧接上一步，说「番茄炒蛋要几个鸡蛋」→ 转写文字**逐字实时上屏**，不是等说完才出现。收口："这一节点解决的是——**能不能跟上**。"

### 节点③ 随时打断（2 分钟，压轴）

**【讲 — 50 秒】**

> AI 播报太长不能插话就很笨。为此我加了**回声能量门控**：AI 播报期间麦克风一直开着，系统维护一个底噪基线——**真人语音能量显著高于基线就判定"有人插话"**，立刻停掉播报进入下一轮；而 AI 自己播报的声音能量低，会被当作回声抑制掉，**不会自己打断自己**。这就是"随时打断"的核心。

**【代码】**（对应 `frontend-2/src/lib/wakeword-stt.ts` 的 `createEchoGate`）

```typescript
// 回声门控：真人语音能量显著高于底噪才放行 + 触发打断
const gateRise = noiseFloor + GATE_RISE;          // 基线 + 涨幅阈值14
if (rms > gateRise) {
  hooks.onHumanSpeechGate();                       // 真人插话 → 打断AI播报
  return true;                                     // 放行推流
}
return false;                                      // AI回声：能量低，抑制
```

**【实操 — 压轴时刻】**

AI 播报到一半，直接插话「先放油！」→ 播报**秒级停止**、进入新一轮收集。收口："这一节点解决的是——**能不能抢话**。"

### 大任务收口（20 秒）

> 降噪唤醒解决"叫得醒"，流式识别解决"跟得上"，随时打断解决"抢得话"——三节点闭环。而且**语音识别出的文字，最终走的就是小任务2那条 `user_text` 通道**，架构只维护一条对话链路。

## 全场收口（30 秒）

> 三步接入完成：视频让系统有眼睛，文字先跑通对话通道，语音把交互升级到免触。**三种输入、一个出口**——无论哪一种方式进来，最终都归一为一条消息发给同一个大模型。这就是我们前端三步接入的全貌。
