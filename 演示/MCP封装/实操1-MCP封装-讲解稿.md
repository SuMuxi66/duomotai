## 第一幕 0:00-0:30 · 为什么封装

【操作】投屏空 IDE，演示文件已在编辑器打开（头部 docstring 可见，先不敲）

【同步讲解】

> 我们厨房的硬件能力其实早就做完了——红外测温、称重、下料机、排气扇，全部挂在 8010 后端上。但它目前只被我们自己的语音前端调用，别的 AI 用不了。
>
> 现在我用 **20 行以内**的代码，把这些硬件封装成 MCP server。封装完，Trae、Cursor、Claude Desktop——**写一次，所有 AI 客户端都能用**。
>
> 动手前先说一个关键架构决策：这个 MCP server **不碰串口**。下料机和称重的板卡在 COM10 串口上，由 8010 后端进程独占——谁并发去开串口，谁就报 PermissionError。所以它是**纯 HTTP 转发**：每个工具就是一行 httpx 请求，发给后端现成的端点。校验逻辑、达标断电，全部复用后端现成的，一行不重写。

（埋伏笔）"整份代码就三个骨架动作：**建实例、挂工具、启动**。看好了——"

## 第二幕 0:30-2:30 · 逐行编写（核心，五站走读）

### 站 1（0:30-0:45）· import 两行

【操作】敲：

```python
import httpx
from mcp.server.mcpserver import MCPServer   # mcp 2.x：FastMCP 已改名 MCPServer
```

【同步讲解】

> 两行 import。顺带踩过一个真实坑：mcp 库 2.x 把 FastMCP 改名叫 MCPServer 了，网上旧教程的导入路径直接跑不起来——所以我们用的是 2.x 的新名字。

### 站 2（0:45-1:00）· 骨架①：建实例

【操作】敲：

```python
mcp = MCPServer("gs-kitchen-hardware")
```

【同步讲解】

> 第一个骨架动作：实例化一个 server。参数只是给客户端看的名字。到这里 MCP server 的本质已经出现了——它就是一个**工具注册表**，接下来我们往里面注册工具。

### 站 3（1:00-1:40）· 骨架②：第一个工具（全稿最核心 40 秒）

【操作】敲：

```python
@mcp.tool()                                  # 骨架②：函数变工具
def get_temperature() -> dict:
    """读取红外测温实时数据（摄氏度）"""      # docstring = AI 看到的工具说明
    return httpx.get("http://127.0.0.1:8010/temperature", timeout=8).json()
```

【同步讲解】

> 这是整份代码**最核心的一行——`@mcp.tool()` 装饰器**。函数头上加这一个装饰器，一个普通的 Python 函数就注册成了 MCP 工具。
>
> 第二个重点是函数底下这行中文注释。它不是普通注释，是 **docstring——AI 看到的工具说明书**。AI 就是靠它决定"什么时候该调这个工具"。所以我写"读取红外测温实时数据"，客户端挂载之后，AI 遇到温度问题自己就知道来调它。
>
> 函数体呢？就一行：httpx.get 发给 8010 的 /temperature 端点——这就是刚才说的**纯转发**：不开串口、不 import 后端，串口还是后端独占。

### 站 4（1:40-2:10）· 写操作工具：下料 + 风扇

【操作】敲：

```python
@mcp.tool()
def dispense_start(target_g: float) -> dict:
    """自动下料 target_g 克，称重达标自动断电"""
    return httpx.post("http://127.0.0.1:8010/dispense/start",
                      json={"target_g": target_g}, timeout=25).json()
```

（fan_on 可只口播不敲，见砍单顺序）

【同步讲解】

> 再注册一个**写操作**——自动下料。两个细节值得说：
>
> 一是参数 `target_g` 带类型，AI 传参必须带克数，类型就是给 AI 的传参约束；
>
> 二是 timeout 我特意给了 25 秒——因为后端启动下料前会等串口就绪，最长 15 秒，超时设短了，客户端会提前断连误判失败。**超时是按下游最坏情况定的**，这是接真硬件的经验。
>
> 排气扇开关同理——大家看到了，**加一个工具就是再加一个四行小函数**，复制粘贴的事。

### 站 5（2:10-2:30）· 骨架③：启动

【操作】敲：

```python
mcp.run()                                    # 骨架③：stdio 启动，客户端自动拉起
```

【同步讲解】

> 最后一个骨架动作：stdio 模式启动。注意它**不占任何端口**——MCP 客户端会把这个文件当子进程自动拉起，通过标准输入输出通信。这就是为什么大家用的时候不需要手动跑任何命令。

## 第三幕 2:30-3:00 · 挂载验证 + 收口

【操作】

1. 切到 [mcpserver.json](../../mcpserver.json)，指出三要素：command（backend venv 的 python）、args（本文件路径）、env（GS_BACKEND_URL 可覆盖后端地址）
2. 切到 MCP 客户端，展示工具列表：`gs-kitchen-hardware` · 3 个工具
3. **现场**在对话框输入："现在厨房温度多少度？" → AI 自主调用 `get_temperature` → 返回真传感器读数

【看到】客户端工具调用痕迹：工具名 get_temperature、无参数、返回 JSON 含真实温度

【同步讲解】

> 把这份配置合并进客户端，就能看到 3 个工具。现场试一下——问它"现在厨房温度多少度"。注意：**是 AI 自己决定**调 get_temperature 的，靠的就是刚才那行 docstring；拿到的也是真传感器的实时读数，不是我提前写死的。
>
> （收口）演示版 3 个工具 17 行；我们的生产版 **11 个工具 119 行**——多出来的 100 行，只是 8 个工具的复制粘贴，加了参数范围校验（下料限 0.5~100 克）和错误降级（后端没起时返回"请确认后端已启动"的提示而不是报错堆栈），**三个骨架动作一行没变**。
>
> 一句话收尾：**一套硬件能力，一个标准接口。**
